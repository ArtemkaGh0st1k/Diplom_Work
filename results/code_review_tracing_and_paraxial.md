## 1. `HarmLens` (Приложение А отчёта НИР-2)

Код запускался в изоляции. Тест: луч на высоте r = 2 мм параллельно оси,
параболическая поверхность P = 100 мм.

### 1.1 Точка пересечения с поверхностью не находится — критично
`beam_lens`, шаг 4. Бисекция идёт по t ∈ [0, (Z_Lens − z0)/az], то есть
только **до плоскости** `Z_Lens`. Поверхность при этом лежит в
`Z_Lens + Section(r)`, где Section ≥ 0.

На обоих концах интервала выполняется `z − Z_Lens < Section`. В итоге
бисекция всегда сходится к t = 0: «точкой пересечения» становится начало
луча.

Тест: старт z0 = −5 мм, найденная точка zL = −5.0000.

- Для луча, параллельного оси, x и y не страдают, поэтому ошибку легко не
  заметить.
- Для наклонных лучей (вторая и последующие линзы) x и y точки пересечения
  неверны на величину a·Δz.

**Как исправить:** правая граница интервала должна быть за поверхностью,
например `tL = (Z_Lens + Thickness − z0)/az`. Перед бисекцией нужно
проверить, что знак `z − Z_Lens − Section(r)` на концах разный.

### 1.2 Знак в векторном законе Снелла перевёрнут — критично
`beam_lens`, шаг 10:

```python
self.axL = n1*ax/n2 - Nx*G/n2
```

Нормаль сонаправлена лучу (N·a = cos θ1 > 0). При такой нормали правильно
`n2·a' = n1·a + G·N`, где G = n2·cos θ2 − n1·cos θ1.

Тест для выпуклой поверхности стекло → воздух (собирающая линза):

| | a'x |
|---|---|
| код | +0.0100 (луч уходит **от** оси) |
| точный Снелл | −0.0100 |

Модуль совпадает, знак противоположный. Для границы воздух → стекло знак
тоже обратный. Получается, что собирающая поверхность работает как
рассеивающая.

Возможно, в C++ нормаль ориентирована иначе и это ошибка порта. Это нужно
сверить с исходником руководителя.

### 1.3 Модель дифракции через масштабирование наклона — физически неточна
`norm_m` умножает наклон грани на kHarm = λ·k/(m·λ0). В малых углах
отклонение луча получается (n(λ) − 1)·k·λ/(m·λ0)·r/P.

По уравнению решётки (Антонов, ф. 13–14) правильно k·λ/(m·λ0)·(n(λ0) − 1)·r/P.
Порядок дифракции **от материала не зависит**. Значит, в модели лишний
множитель (n(λ) − 1)/(n(λ0) − 1). Для BK7 в диапазоне 400–1000 нм это от
−2.2% до +2.3% оптической силы, то есть ±4 мм при f = 200 мм.

**Как исправить:** вместо подстройки нормали отклонять луч по локальному
уравнению решётки: n'·sin θ' = n·sin θ + k·λ/Λ(r), где Λ(r) — локальный
период зон.

### 1.4 Выбор порядка в `harm_lam` не учитывает дисперсию
Порядок выбирается как ближайшее целое к m·λ0/λ. Правильно — ближайшее целое
к H·(n(λ) − 1)/λ = m·(λ0/λ)·(n(λ) − 1)/(n(λ0) − 1) (Антонов, ф. 3).

### 1.5 Мелкие замечания
- `harm_lam` падает с `ZeroDivisionError` при m·λ0/λ < 0.5, например
  `harm_lam(1, 532, 1500)`. В видимом диапазоне при m = 7 это не
  проявляется.
- `norm`/`norm_m` считают производную конечной разностью. На скачке зоны
  `Section[rd+1] − Section[rd] = −h`, наклон получается огромным, и луч,
  попавший на границу зоны, улетает. Нужно пропускать точки скачка.
- `harmonization` берёт `Section mod h` от полной толщины. Первая граница
  зоны смещается на `Thickness mod h`, и радиусы зон перестают совпадать с
  r_i² = 2·i·m·λ0·f0. Нужно брать `(Section − Section[0]) mod h`.
- В комментарии к `P` написано «фокус для параболической». На самом деле
  P — радиус кривизны при вершине. Фокус линзы равен P/(n − 1).
- n1 и n2 — константы, дисперсия в показанном коде не используется.

## 2. «Трассировщики» в репозитории

### 2.1 `RayTracer` / `QuickRayTracer` — не трассировка
Это та же ABCD-прогонка, что и `base.py`. Проверено: `RayTracer` совпадает с
`−A/C` матрицы системы до 4·10⁻¹⁷.

Отличия от `base.py`:
- `round()` (целый k) вместо `custom_round` (k кратно 0.5);
- задний отрезок |h/α| = BFL вместо EFL = −1/C;
- 50 длин волн вместо 601.

Из-за этого в отчёте НИР-2 и в `results/analysis_report.md` сравниваются
две **разные параксиальные** величины, а не параксиальный расчёт и
трассировка:

| 2 линзы, h = 7 / 7.42 мкм, f0 = 200 мм, d = 10 мм | Δf |
|---|---|
| `base.py` (EFL, custom_round, 601 λ) | 6.59 мм |
| `RayTracer` (BFL, round, 50 λ) | 16.24 мм |
| то же через ABCD −A/C | 16.24 мм |

Значения 6.5237 и 16.2416 мм из отчёта объясняются полностью: разница не
связана с трассировкой.

### 2.2 `RealRayTracer` и `AdvancedRealRayTracer` — выдуманная аберрация
Сферическая аберрация здесь задаётся эмпирической поправкой
Φ·(1 + SA3·h²) с подобранным коэффициентом:
- `SA3 = 5000 м⁻²` в `RealRayTracer`;
- `0.5/R²` в `AdvancedRealRayTracer`.

У идеальной дифракционной линзы такой зависимости нет. Её параметры должны
получаться из геометрии, а не задаваться.

Ещё ошибки:
- в `advanced_real_tracing.py` не передаётся `lens_index`, поэтому для всех
  линз берётся `focus_0[1]`;
- `calculate_exact_phase_profile` нигде не используется;
- «волновая ошибка» `abs(SA)*(2π/λ)*1e-6` размерностно бессмысленна.

Вывод из НИР-2 «реальная трассировка сокращает фокальный отрезок в 2.6–3.2
раза» на этом коде **не держится**. Это стоит обсудить с научным
руководителем до следующего отчёта.

## 3. Ваш параксиальный расчёт `BaseLensOptimizer.lmbd_focus_dict`

Что верно:
- матрицы R и T, их порядок перемножения (reverse + reduce);
- EFL = −1/C;
- приведённое расстояние d/n;
- коэффициенты Селлмейера для BK7 (n(550 нм) = 1.5185);
- выбор порядка через фазовую задержку H·(n(λ) − 1)/λ — идея правильная.

### 3.1 Формула фокуса содержит n(λ) вместо n(λ0) — существенно
Сейчас в коде:

```python
lambda_0 = height * (n(λ) - 1) / harmonica   # пересчитывается на каждой λ
focus = harmonica * lambda_0 / (k * λ) * f0  # = H·(n(λ)-1)·f0/(k·λ)
```

По теории (Антонов, ф. 14; Sweeney, ф. 1) f = m·λ0·f0/(k·λ) = H·(n(λ0) − 1)·f0/(k·λ).
λ0 — **фиксированная** расчётная длина волны: она задаёт радиусы зон.

Код ошибочно добавляет множитель (n(λ) − 1)/(n(λ0) − 1). По сути, он
компенсирует дисперсию материала, которой в формуле фокуса нет.

### 3.2 `harmonica` не влияет на результат — существенно
m сокращается: `harmonica * lambda_0 = H·(n(λ) − 1)`.

Проверка: замена гармоник 7 / 7.5 на 3 / 11 меняет f(λ) не больше чем на
4·10⁻¹⁷ м. Значит, «гармоника 7.5» из датасетов и формула (4.1) отчёта на
расчёт не влияют.

Гармоника m по определению целая (Sweeney, Антонов). Нецелое m = 7.5 означает
полуволновой скачок на λ0, и энергия делится между двумя порядками.

### 3.3 Округление k до 0.5 (`custom_round`) — существенно
Полуцелых порядков дифракции нет: при α = k + 0.5 энергия делится примерно
по 40% между порядками k и k + 1 (Sweeney). Фокус «k = 7.5» лежит
посередине между двумя реальными фокусами, а там света почти нет.

Это искусственно уменьшает Δf: 6.59 мм против 17.80 мм при целом k для тех
же высот. Нынешний оптимум по h, скорее всего, найден на этом артефакте.

Хак `if k == 0: k = 0.5` прикрывает ту же проблему. Правильно — проверять,
что α ≥ 0.5, и иначе не считать эту λ (линза в рабочем режиме там не
работает).

Если нужно учесть смешение порядков, есть корректный вариант: считать
«энергетический» фокус как взвешенное по η_k = sinc²(α − k) среднее порядков
k и k + 1. Либо минимизировать Δf только по резонансным λ_k.

### 3.4 Фокальный отрезок по EFL, а не по положению фокуса
Для фокального сдвига на приёмнике физически нужен задний отрезок
BFL = −A/C. В текущей конфигурации разница небольшая (6.59 против 6.87 мм),
но при больших d и большем числе линз она растёт.

### 3.5 Мелкие замечания
- Ветка `except` в `lmbd_focus_dict`: для `len(heights) == 2` сработает
  `else` второго `if`, и вызов упадёт с «Число высот должно быть равно 2 или
  3». Нужно `elif`. Кроме того, невалидный датасет молча подменяется
  дефолтным: лучше пробрасывать ошибку.
- `dataset['refractive_index']` (1.5) используется только для высоты по
  умолчанию, а в расчёте всегда стоит BK7. Это рассогласование.
- `dataset['lambda_0']` (550 нм) при заданных высотах игнорируется.
- В отчёте указан шаг по λ 0.5 нм, в коде 601 точка на 400–1000 нм, то есть
  шаг 1 нм.
- Тема работы — «видимый диапазон», а расчёт ведётся до 1000 нм.
- `n_bk7` скопирован в пять файлов. Его стоит вынести в `utils`.

### 3.6 Сводка: как меняется Δf при исправлениях
2 линзы, те же параметры. «Теория» означает f = m·λ0·f0/(k·λ), где λ0 найдено
из H = m·λ0/(n(λ0) − 1).

| округление k | модель f | EFL | BFL |
|---|---|---|---|
| до 0.5 (сейчас) | код | 6.59 мм | 6.87 мм |
| до 0.5 | теория | 9.58 мм | 9.80 мм |
| целое | код | 17.80 мм | 17.83 мм |
| целое | теория | 17.70 мм | 17.73 мм |

## 4. Что нужно для полной проверки порта

1. Положить в репозиторий **Python-файл `HarmLens`** целиком (с `BeamAxe` и
   драйвером системы), а по возможности и **исходник C++** руководителя. Тогда
   можно сверить построчно и выяснить, где появились ошибки 1.1–1.2: в порте
   или в оригинале.

   - (а) зоны фиксированы (m, λ0, f0), а меняется только глубина рельефа H;
     тогда H влияет лишь на выбор порядка;
   - (б) меняется расчётная λ0, то есть H и радиусы зон вместе.

   От этого зависит, как переписать `lmbd_focus_dict`.
3. Добавить эталонные тесты:
   - одиночная линза на резонансной λ_k даёт f = m·λ0·f0/(k·λk);
   - трассировка лучей у оси совпадает с ABCD;
   - собирающая поверхность отклоняет луч к оси.
