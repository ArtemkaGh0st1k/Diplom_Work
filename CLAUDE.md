# Diplom_Work — инструкции для Claude

Тема работы: Моделирование фокального сдвига системы гармо
нических линз в видимом диапазоне методом трассировки лучей

Главная функция параксиального расчёта при помощи матричной оптики
лежит по пути: optimizers / base.py / lmbd_focus_dict

Магистерская работа: оптимизация систем из 2–5 гармонических (многопорядковых)
дифракционных линз. Подбираются высоты микрорельефа h, гармоники m и расстояния
между линзами так, чтобы минимизировать длину фокального отрезка в заданном
спектральном диапазоне. Используются параксиальный расчёт (ABCD-матрицы) и
реальная трассировка лучей.

## Структура

- `optimizers/` — целевая функция (`base.py`), оптимизаторы для 2–5 линз, трассировка
- `data/` — исходные датасеты и тестовые массивы
- `utils/` — единицы измерения, ключи, конвертеры
- `validators/` — проверка входных данных
- `gui/` — интерфейс
- `results/` — отчёты, графики, материалы НИР и презентации
- `garbage/` — старые эксперименты, не трогать без просьбы
- `theory/` — теоретические материалы пользователя (см. ниже)

## Правила работы

### Git — ничего не коммитить
- **Никогда** не выполнять `git commit`, `git push`, `git merge`, `git rebase`,
  `git reset`, `git stash`, `git checkout`/`switch` с переключением веток и любые
  другие операции, меняющие историю или состояние репозитория.
- `git add` тоже не делать. Разрешены только чтение: `git status`, `git diff`, `git log`.
- Все изменения остаются в рабочей копии — что и когда коммитить, решает пользователь.

### Стиль кода
- Python-код должен соответствовать PEP 8 (+ PEP 257 для docstring, аннотации типов).
- Docstring и комментарии — на русском, как в существующем коде.
- После заметных изменений кода — прогонять ревью агентом `pep8-code-reviewer`.
- Не менять формулы и физические константы «попутно» при стилистических правках.

### Предметная область
- Перед работой с физикой/формулами — свериться с `theory/NOTES.md` (конспект теории).
- Внимательно следить за единицами (м / мм / мкм / нм) — см. `utils/unit.py`.

## Папка theory/

Пользователь складывает сюда теорию (PDF, DOCX, статьи, конспекты). Когда
появляются новые файлы и пользователь просит изучить их — прочитать, выделить
ключевые формулы, обозначения, допущения и связь с кодом, и записать/обновить
конспект в `theory/NOTES.md`. Исходные файлы не изменять.
